# 坑 02：GPU 启动费摊薄（docling-serve 常驻）

## 问题

docling 每次进程启动要付 ~135s 固定开销：

```
模型加载（几百 MB 进内存）  ~90s
GPU 图编译（torch inductor）  ~45s
```

这个费用**与页数无关**——单页和 100 页都付。每份文档独立进程 = 每份都重付，批量 20 份 = 20 × 135s ≈ 45 分钟。

## 解法：常驻服务，启动费只付一次

```
┌─ 客户端（docling.sh）────────────┐
│  POST http://127.0.0.1:5001/convert │──┐
│  失败/未起 → 回退单进程             │  │
└──────────────────────────────────┘  ▼
                             ┌─ 常驻服务（docling_server.py）──────┐
                             │  启动时预热：加载 light + full 两个   │
                             │  模型 + GPU 编译（~4-5 分钟，一次性） │
                             │  之后每份转换：~1s/页                │
                             └──────────────────────────────────┘
```

## 实测数据（RTX 4060 + cu126 torch）

| 模式 | 单份（1 页扫描件） | 批量 3 份混合 |
|---|---|---|
| 单进程（每次付启动费） | ~135s | ~280s |
| 常驻 serve（预热后） | **~1s** | **~4s** |

## 设计要点

1. **双模型预热**：扫描件走 light（关表格/公式），文字版/混合走 full——两个都预热，任何模式首次请求都秒级
2. **服务端预热，客户端不预热**：`start` 脚本带 warm 文件参数，服务启动时在后台把编译费付掉；客户端 shim 无感
3. **自动回退**：serve 没起/挂了 → shim 回退单进程（慢但可用），绝不静默失败
4. **启动费 ~135s 是"一次性"还是"每次"取决于是否复用进程**——这是关键认知，也是 serve 方案的全部价值

## 为什么不用官方 docling-serve？

官方 `docling-serve` 包依赖 grpcio，**Python 3.14 无 wheel** → 源码编译 → 需要 cl.exe（VS Build Tools）→ 撞墙。自建 FastAPI（docling 自带 fastapi+uvicorn 依赖，零新增）等效实现，无 grpcio 包袱。

# 坑 05：视觉质检环（AI 看得见自己的产出）

> 2026-08-14 实测。编辑链产出 docx 后，AI 怎么知道排版好不好？——渲染成图，用视觉模型看图。

## 为什么必须有这一环

文本提取/读 XML 发现不了**布局缺陷**（文字截断/溢出/重叠/缺字/间距漂移）。"文档做没做好，只有渲染出来看了才知道"——这是 render→verify→iterate 铁律的核心，也是 AI 代工和"盲写文档"的分水岭。

## 轻量质检 shim（零依赖，推荐）

仓库内置 `src/qa.sh`——**纯 urllib 调 OpenAI 兼容视觉端点**（默认火山豆包），不需要 Qwen-MM-Plugins/MCP、不依赖重启、不装任何视觉工具：

```bash
# 1. 渲染成 PDF/PNG（中文路径直接可用！比 x2t 的英文路径坑顺）
aioffice render 报告.docx --to pdf -o render.pdf     # 或 --to png
# 2. PDF 分页转 PNG
python -c "import fitz; [p.get_pixmap(dpi=100).save(f'qa_p{i}.png') for i,p in enumerate(fitz.open('render.pdf'))]"
# 3. 质检（只需视觉端点 key）
export ARK_API_KEY=xxx
qa.sh qa_p0.png        # 默认查截断/豆腐块/错位/可读性
qa.sh qa_p0.png "检查表格是否越界"   # 自定义问题
```

为什么不用重型视觉工具：质检本质 = "一张图 + 一个问题 + 返回文本"，`qa.sh` 30 行 urllib 就够；Qwen-MM-Plugins 的 grounding/segmentation/omni 全家桶对质检是负担，MCP 进程还引入重启依赖。**注意**：`qa.sh` 的 key 必须来自 `ARK_API_KEY` 环境变量（公开仓库不带 key）。

## 关键点

1. **aioffice render 是质检渲染首选**——中文路径直接转 PDF/PNG，不用 x2t 的"复制到英文临时路径"；还能 `--scope` 只渲染某个节点
2. **视觉模型**：默认火山豆包（`ARK_API_KEY`），任何 OpenAI 兼容视觉端点可换（改 `ARK_BASE_URL`/`ARK_VISION_MODEL`）
3. **质检是循环不是终点**：有缺陷 → 回编辑链（aioffice edit / XML 手术）→ 重渲染 → 再看，直到干净才交付

## 检查项优先级（按出现频率）

1. 文字溢出/截断（最常见，永远第一个查）
2. 元素重叠（文字穿形状、线穿字）
3. 中文豆腐块/乱码
4. 公式/图片错位
5. 表格越界
6. 占位符残留（lorem/TODO/[insert]）

## 实测案例（2026-08-14 真实 PPT 质检）

- 输入：8.6MB 真实中期报告 PPTX（18 页），aioffice 改文字+加形状后渲染 PDF
- 质检结果：编辑内容（"中期检查汇报·v2"、"感谢聆听"）确认显示 ✅；**同时抓到源文件自带缺陷**——大量编辑残留占位符（`[image] 图片87` 等）与占位框错位 ❌
- 启示：视觉质检看的是"渲染结果"，**区分源文件自带缺陷 vs 编辑引入缺陷**需对比基线——用 `aioffice diff 改前 改后`（语义对比，改了什么可追溯）
